# 공휴일 데이터 (한국천문연구원 특일 정보 API)

지금 `src/data/holidays.js`의 공휴일은 직접 적은 것이라 **틀린 곳이 있습니다.** (2026년 4일, 2027년 7일 누락 등) 공식 출처에서 받아 오도록 바꾸는 작업입니다.

- 상태: **준비 완료, 인증키 대기 중.** 동기화 스크립트와 시험은 만들어 두었고, 앱은 아직 예전 데이터를 씁니다.
- 출처: 한국천문연구원 특일 정보 (공공데이터포털 15012690)

## 어떻게 돌아가는가

```
[내 컴퓨터]                                          [앱]
npm run sync-holidays ──(인증키)──▶ 공공데이터포털 API
        │
        └─▶ src/data/holidays.generated.json  ──(커밋)──▶  앱이 이 JSON을 읽어서 표시
```

- **인증키는 내 컴퓨터의 `.env` 파일에만** 있고, 스크립트가 쓸 때만 읽습니다. 앱(브라우저)에는 결과 파일(JSON)만 들어가므로 키가 배포물에 섞이지 않습니다.
- 앱이 브라우저에서 직접 API를 부르면 키가 모든 방문자에게 보이게 됩니다. 그래서 이 방식을 택했습니다.
- 스크립트는 새 패키지 없이 Node 기본 기능만 씁니다. 파일: `scripts/sync-holidays.mjs`(실행), `scripts/holidays-fetch.mjs`(요청), `scripts/holidays-parse.mjs`(응답 해석)

## 인증키 발급 순서 (직접 하실 일)

1. [공공데이터포털(data.go.kr)](https://www.data.go.kr)에 로그인합니다. (회원가입은 무료)
2. 검색창에 **한국천문연구원 특일 정보**를 검색해서 "한국천문연구원_특일 정보"(Open API)를 엽니다.
3. **활용신청**을 누르고, 활용 목적에 "개인 달력 앱의 공휴일 표시" 정도로 적어 신청합니다. (이 API는 보통 바로 승인됩니다)
4. 로그인한 상태에서 **마이페이지 → 데이터활용 → Open API**에서 이 API의 **일반 인증키**를 찾습니다. "Encoding"과 "Decoding" 두 가지가 보이는데, **어느 쪽을 복사해도 됩니다.** (스크립트가 알아서 맞춥니다)
5. 프로젝트 폴더에서 터미널로 아래를 실행해 `.env` 파일을 만들고, 편집기로 열어 `여기에_발급받은_인증키`를 복사한 키로 바꿉니다.
   ```
   cp .env.example .env
   ```
6. **키는 채팅, 코드, 커밋 메시지, 스크린샷 어디에도 붙이지 마세요.** `.env`는 git이 무시하도록 설정되어 있어서 커밋되지 않습니다. (`git status`에 `.env`가 보이면 알려 주세요)

> 발급 직후에는 키가 아직 적용되지 않아 "등록되지 않은 인증키" 오류가 날 수 있습니다. 그러면 잠시 뒤에 다시 시도하세요.

## 실행

```
npm run sync-holidays -- --dry-run     파일은 쓰지 않고, 받은 결과와 지금 앱 데이터의 차이만 보여 줍니다 (먼저 이것부터)
npm run sync-holidays                  결과를 src/data/holidays.generated.json 에 저장합니다
npm run sync-holidays -- 2026 2027     연도를 직접 정할 때
```

- 기본 연도는 앱의 연도 선택지와 같은 범위(올해 −1년 ~ +3년)입니다.
- 하나라도 실패하면 **파일을 바꾸지 않습니다.** (일부만 갱신되는 일이 없습니다)
- API에 아직 데이터가 없는 해(고시 전인 먼 미래)는 이전 값을 그대로 둡니다.
- 출력의 `+`는 앱에 없던 날, `-`는 API에 없는 날, `~`는 이름이 다른 날입니다.

## 키를 받은 뒤 확인할 것 (실제 응답으로)

스크립트는 공개된 사용 예시를 바탕으로 만들었습니다. 아래는 **실제 응답으로 확인해야 하는** 항목입니다. (확인되면 이 목록을 지웁니다)

1. 응답 모양이 시험에 쓴 가짜 응답(`response.body.items.item`, `locdate`, `dateName`)과 같은가
2. 2026년 4일 누락분(노동절 5/1, 지방선거 6/3, 제헌절 7/17, 개천절 대체 10/5)이 들어 있는가
3. 임시공휴일이 포함되는가 (공식 페이지에는 설명이 없습니다)
4. 2028년 이후 데이터가 있는가 (월력요항은 전년 6월 말쯤 나오므로 2028년분은 2027년 6월 말쯤 나올 것으로 추정)
5. 이름이 길어서 날짜 칸(120px)에서 잘리지 않는가 (예: "대체공휴일(부처님 오신 날)")

## 그다음 단계 (키 확인 후)

1. `npm run sync-holidays`로 `holidays.generated.json`을 만든다.
2. `src/data/holidays.js`가 이 JSON을 읽도록 바꾼다. 내보내는 모양(`{ 연도: { 'YYYY-MM-DD': '이름' } }`)은 그대로 둬서 `DayCell`은 건드리지 않는다.
   - 주의: 동기화 스크립트가 지금 `holidays.js`를 불러와 "현재 앱 데이터와의 차이"를 보여 주므로, 바꾼 뒤에는 이 비교 방식도 함께 손봐야 합니다. (Node는 JSON을 그냥 import할 수 없습니다)
3. 시험을 고치고, 해마다 6월 말 이후에 한 번씩 `npm run sync-holidays`를 돌린다.
